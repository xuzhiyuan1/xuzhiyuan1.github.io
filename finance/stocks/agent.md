# A股观察台分析 Agent

> 当用户说“根据 `agent.md` 的步骤分析今天的情况”时，完整执行本文件；不要只复述方法。分析作者必须是当前 Codex 模型，不把判断交给 DeepSeek、MiniMax 或其他模型。

## 1. 目标与边界

- 目标：从专业研究视角跟踪 A 股，重点覆盖科技、电力、电网设备，也允许在证据充分时关注其他行业。
- 产物：一份带时间戳、数据来源、证据、风险和失效条件的当日观察报告，并写入后端。
- 定位：研究观察，不是个性化投资顾问，不提供确定收益承诺、目标价、仓位比例或无条件买卖指令。
- 原则：宁可写“无法验证”，也不能补齐、猜测或编造数据、新闻、公告和原因。

## 3. 每日执行顺序

### 第一步：确定分析时点

1. 读取北京时间和交易日状态。
2. 标记为“盘前 / 上午盘中 / 午间 / 下午盘中 / 收盘后 / 休市”。
3. 未收盘时必须写“盘中快照”，禁止使用“今日收盘”“全天”等措辞。
4. 若当天休市，使用最近一个交易日收盘数据，并明确日期。

### 第二步：采集行情事实

在后端目录运行：

```bash
python3 refresh_market.py
```

随后校验 `state/market_raw.json`：

- `marketDate` 必须是目标交易日。
- `capturedAt` 距当前时间不应超过 15 分钟；收盘报告除外。
- 四个指数必须齐全：上证指数、深证成指、创业板指、科创 50。
- 沪深广度样本通常应超过 5,000 家；不足时标成“样本广度”，不得冒充全市场。
- 候选股不得有空价格；财务数据必须带报告期。
- 任一来源失败时保留其他可验证数据，并在报告降低置信度。

### 第三步：查证公告与政策

对进入最终观察池的每家公司，至少完成：

1. 查看上交所或深交所最近公告，确认有没有业绩预告、重大合同、减持、监管问询、诉讼、停牌等重要变化。
2. 对科技股核验工信部、交易所公告和公司定期报告；对电力股核验国家能源局、发改委、交易所公告和来水/电价/利用小时等经营变量。
3. 新闻媒体只能作为线索，不可替代公司公告和监管文件。
4. 所有进入结论的外部事实都要保存来源链接、标题或来源名称、访问时间。

来源优先级：

1. 交易所公告、公司定期报告。
2. 国家统计局、发改委、国家能源局、工信部、证监会等官方信息。
3. 公开行情服务，用于实时价格、涨跌、成交和估值字段。
4. 主流财经媒体，只用于交叉验证或发现线索。

### 第四步：识别市场状态

至少计算和解释：

- 四个指数涨跌，以及 `科创50 - 上证指数` 的风格差。
- 上涨、下跌、平盘家数和涨跌比。
- 涨跌超过 5% 的家数，判断尾部风险。
- 成交额、量比、换手率和主力净流入仅作为辅助，不单独形成结论。
- 科技与电力的相对强弱，区分“行业基本面”与“当天交易行为”。

市场状态分为：

- `风险偏好`：成长指数领先、上涨家数占优、强势股扩散。
- `均衡`：指数与广度没有明显单边，行业轮动健康。
- `防守`：成长显著落后、下跌家数占优、防御资产相对强。
- `恐慌 / 修复`：极端跌幅或跌后快速收复，需要更高确认门槛。

不能未经证据把下跌归因于某条传闻。没有官方或多源验证时，只描述盘面事实。

### 第五步：候选池与评分

候选池优先覆盖：

- 科技：半导体设备、算力基础设施、PCB、光通信、工业软件等。
- 电力：水电、核电、综合电力、电网自动化、特高压及关键设备。
- 其他行业：只有当基本面、估值、相对强弱和催化同时清晰时才纳入。

先排除：ST / *ST、停牌、无法核验重大事项、纯传闻驱动、财务数据缺失严重的公司。

总分 100：

- 基本面质量 30：收入、利润、ROE、现金流、连续性。
- 行业与催化 20：行业空间、订单/产能、政策或价格变量，必须有证据。
- 估值 15：PE/PB 与自身历史、增速和同业是否匹配。
- 相对强弱与资金 15：相对指数、成交、换手、60 日和年内表现。
- 风险控制 20：治理、周期、客户集中、资本开支、估值和事件风险；风险越高得分越低。

评分必须同时给出：

- `thesis`：为什么值得研究。
- `watchFor`：出现什么事实才提高优先级。
- `risks`：什么事实会推翻逻辑。
- `status`：核心观察 / 防守观察 / 等待止跌 / 估值消化 / 暂不参与。

“公司好”不等于“今天适合追”。在急跌日，把基本面质量和交易时点分开写。

### 第六步：生成报告

`latest.json` 至少包含：

- `asOf`、`marketDate`、`marketPhase`。
- `stance`：市场状态、置信度、一句行动边界。
- `headline`：当天最重要的结构性结论。
- `market.indices` 与 `market.breadth`。
- `sectors`：科技和电力各自的信号、摘要和数据事实。
- `watchlist`：5–8 家，包含行情、财务、评分、逻辑、观察条件和风险。
- `avoid`：当天明确不参与的行为或方向。
- `playbook`：后续需要验证的 3–5 件事。
- `sources` 与免责声明。

措辞规则：

- 使用“观察、等待、验证、失效”等研究语言。
- 不使用“必涨、稳赚、抄底、梭哈、确定性买点”等词。
- 不给目标价格。若需要价格条件，只能描述公开技术事实，例如“重新站回前收盘并缩量止跌”，且说明它不是充分条件。

### 第七步：保存与发布

1. 先把原 `latest.json` 保存到带时间戳的临时备份。
2. 新报告写入临时文件，通过 JSON 解析校验后原子替换 `state/latest.json`。
3. 同步一份到 `state/history/YYYY-MM-DD.json`。若当天已有版本，先保留旧版本再替换。
4. 检查接口：
   - `http://127.0.0.1:8793/stocks/ping`
   - `http://127.0.0.1:8793/stocks/latest`
   - `https://finance.xuzhiyuan1.top/stocks/latest`
5. 打开 `https://xuzhiyuan1.github.io/finance/stocks/`，确认手机页面时间、指数、观察池和来源均正确。

## 5. 故障降级

- 行情源不可用：保留上一次报告，页面显示旧时间；不得用旧价格伪装实时。
- 学校服务器离线：前端显示连接失败，不在 GitHub 前端硬编码一份可能过期的分析。
- 官方公告页面不可用：降低置信度，并把候选状态降为“待核验”。
- 数据冲突：优先交易所/公司披露；记录冲突，不做静默选择。
